## 先打开这里

1. 解压整个文件夹，用 Unity Hub 添加包含 `Assets`、`Packages`、`ProjectSettings` 的目录。
2. 使用原工程版本 **Unity 6000.3.20f1**，等待 Package Manager 导入完成。

4. 电脑模拟用同一菜单下的 **2 - Open Simulator scene**。IP2b 的来源卡与图层面板在 Play 时创建。

## 实际操作

| 想做什么 | 操作 |
|---|---|
| 选背景 | BEGIN → 指向照片按 Trigger 选中，再按一次或用 Grip 拿近。 |
| 直接试新功能 | 首次选好背景后，S 球旁出现 `NEW · PHOTO CUTOUTS`。直接 Grip 抓住半浮出小照片的冲浪者，再放到背景上。 |
| 换一个主体 | 打开 **S 球 → FROM PHOTO**，左侧出现两张来源细节照片。Grip 抓住冲浪者或铁塔。 |
| 拼到背景 | 将主体移到目标照片附近，看到半透明落点、目标边框和 RELEASE TO PLACE 后松开 Grip；成功后短暂显示 PLACED。也可放到照片墙中的另一张照片上。 |
| 调大小／旋转 | 两手 Grip 调大小；缩放期间锁定旋转。单手握持时转动手腕旋转。 |
| 加文字 | T 球 → 选择短语或输入 → 创建文字 → 抓到照片上。 |
| 改前后关系 | 抓取过的元素成为当前图层；带重叠图标的 **FORWARD／BACKWARD** 每次移动一层。短暂提示 IN FRONT OF／BEHIND 与被跨过的元素名称。**NEXT LAYER** 可选到被挡住的图层。 |
| 删除／恢复 | 把已放置元素移到左侧垃圾箱内部再松手，5 秒内点 UNDO。此版本采用放入式删除，避免从左侧来源卡移动时被误判为抛向垃圾箱。 |
| 查看最终图 | 蓝色 Publish 球 → **FLAT STORY PREVIEW**。检查文字与主体的遮挡，再确认发布或 BACK TO EDIT。 |
| 放错位置 | 已放置元素回到上一次位置；刚拿出的主体回到来源卡，可重新抓取。 |

来源卡只显示原照片的局部细节，便于抓取很小的主体。六张原照片均保留。
发布是本地模拟，不会上传社交平台。重启／重置不会保存拼贴草稿；试验事件日志会保留。

## 新入口的表现

- **何时出现：**第一次把背景照片选入编辑状态后。BEGIN 和浏览照片墙不会提前消耗示范。
- **看见什么：**S 球旁的小照片、半浮出的可抓取冲浪者、NEW 标签；上方独立小样标为 `EXAMPLE`，用 Auckland 背景、冲浪者和 WEEKEND 文字展示拼贴。
- **两秒示范：**一个不接受输入的副本从入口抬起、移向小样并贴上。真实抓取目标始终静止，示范不写入用户的照片或编辑记录。
- **如何停止：**指向外露主体时停止动画，方便瞄准；抓取元素或点编辑工具时收起 NEW 与小样。普通的 `PHOTO CUTOUTS` 小入口继续保留。
- **再次进入：**返回相册、改选照片或返回编辑都不会重复自动播放。RESET 为下一位参与者重新启用首次示范。
- **与其他面板共存：**文字／贴纸／完整来源面板打开时，小入口隐藏，关闭面板后恢复；已经抓在手里的主体保持可见。

`ImmersiveStory` Inspector 的 **Enable Cutout Discovery** 默认开启；关闭它可查看前一版仅有菜单入口的方式。课堂正式测试请统一这一设置并记录版本。

## 新版放置反馈

- 预览与实际松手共用目标选择、边缘贴合、缩小适配和图层深度计算。已有图层重新移动时保留原顺序；移到另一张照片时进入其最前层。
- 半透明副本只复制视觉内容，不带抓取组件、碰撞体或控制器，也不加入用户的图层列表或最终导出。
- 目标照片已满、离照片太远、进入垃圾箱时，不显示有效落点。原有无效放置返回／删除与 Undo 逻辑继续生效。
- 自动缩小的预览标明 RESIZED TO FIT。文字和图形贴纸也使用相同的放置判定与视觉副本。
- 放置确认约 0.7 秒；图层前后提示约 1.1 秒。回到相册、重置或退出编辑时收起。
- `Enable Placement Feedback` 默认开启。正式课堂测试请统一设置；BEGIN 后的配置事件会记录版本、引导开关和放置反馈开关。

## 五分钟试用任务

主持用的详细步骤、帮助规则、结果编码、研究段落和参考文献都在 `IP2b_TESTING_PLAN.md`。

1. 约 30 秒：只说明 Trigger、Grip、两手缩放，请参与者选背景。
2. 约 20 秒：自由探索；先不指向新增入口，记录主动尝试与产品示范曝光。
3. 约 1 分 50 秒：请他“做一张愿意分享的旅行 Story，把另一张照片的主体放进背景，并加一句短文字”，布局自由。
4. 约 50 秒：请他让主体挡住部分文字，并解释哪个在前面，观察是否独立完成。
5. 约 30 秒：检查平面预览，再返回修改或完成模拟发布。
6. 约 25 秒：有余裕才测试删除／撤销，否则继续主任务并标记未测。
7. 最后约 35 秒：询问自然程度、舒适度及“是什么让你知道可以松手”。

`IP2b_OBSERVATIONS.csv` 为每人一行的空表；`IP2b_EVENT_NOTES.csv` 记录提示原话、错误和关键时刻。结果用 I（无额外主持人帮助）、A（帮助后完成）、F（尝试失败）、N（未测／中断），详见测试计划。产品示范与主持人的帮助分开记录。

“第一次尝试抓取”由观察者计时，可能包括未抓到；日志的 `cutout_entry_used` 只表示第一次**成功抓到**。两者分别记录。单纯确认发布不代表完成所有子任务。本包没有新参与者结果。

11. 旋转并缩放照片，再将过大主体移到边缘，预览与自动适配一致；重复单手、双手操作，检查文字仍清楚。

13. 在有遮挡的多层构图中，后层移动预览仍在后方，跨照片放置进入目标最前层；两个图层按钮的图标、文字与真实遮挡对应。
14. 松手、追踪中断、RESET、回相册及进入最终预览后均无残留副本；最终平面图不包含落点边框／提示。
15. 连续重复抓取至少十次，观察性能、重影、输入命中与材质是否正常；记录真机结果，不把源码检查当成通过。

## 版本边界与检查状态

- 两个透明主体是**预处理的 AI 辅助素材**，对应现有照片；生成过程可能重建细节，不是原图的像素级分割。运行时没有 AI 抠图、任意照片分割或在线服务。
- 本次开发环境没有 Unity Editor／Quest。已经做源码语法与静态资源检查；**没有声称 Unity 编译、Shader 编译、EditMode 测试、Play Mode、APK 打包或真机测试通过**。
- 共附 20 个 IP2b EditMode 测试用例：原有 7 个放置／图层、5 个引导状态，加上 8 个预览与实际落点一致、无副作用、容量、垃圾箱及图层深度用例。必须在 Unity 中实际运行。
- 平面预览沿用本工程的 **Built-in Render Pipeline**，用单独的正交相机和 RenderTexture 捕获。不要直接改成 URP；需要相应调整预览实现。
- 详细变更与素材来源见 `IP2b_IMPLEMENTATION.md`，静态检查结果见 `IP2b_VALIDATION.txt`。旧目录中的 IP2a README／设计记录是历史资料。
